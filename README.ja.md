# claude-mods

[English](README.md) | 日本語

個人用の Claude Code mod（function hook の plugin）集です。1 つの marketplace として公開しています。

## インストール

ターミナルのセッションのプロンプトで:

```
/plugin install <mod> --marketplace simota/claude-mods
```

シェルから:

```
claude plugin install <mod> --marketplace simota/claude-mods
```

このリポジトリは private です。インストールには、GitHub での読み取り権限と、そのマシンにある github.com 用の git 認証情報（SSH 鍵、または `gh auth login` のあと `gh auth setup-git`）が必要です。

## 使い方

設定は、セッション内では `/plugin configure <mod>@simota-mods`、シェルからは次のコマンドで変えられます。

```
echo '{"enabled":"true"}' | claude plugin configure <mod>@simota-mods --values-stdin
```

`/plugin configure` で変えた設定はその場で mod を読み込み直して反映され、シェルから変えた設定は再起動後に反映されます。入力欄の上の帯は積み重なります。各 mod は、他の mod が描いた内容の上に自分の行を描きます。

### agent-pane

- `/agent-pane` でペインを開きます。実行中のサブエージェントが経過時間付きで先に並び、その後に完了したものが ✓/✗ と所要時間付きで並びます。結果が分からないまま一覧から消えたバックグラウンド実行は `? 結果不明`、teammate やリモートでの起動は `↗ 起動済み（追跡外）` と出ます。
- フルスクリーンのターミナルでは、セッションで最初に Agent を呼んだときに 1 回だけ自動で開きます（リロードしても再び開きません）。
- 実行中のものがある間は、ステータス行に `agents: N running` と出ます。

### done-gate

コマンドはなく、自動で働きます。

- ファイルを編集したあとにテスト・lint・型チェック・ビルドが成功しないままターンが終わると、「未検証の変更があります」の帯が出ます。チェックが成功するか「閉じる」を押すまで残ります。判定するのはコマンドが実行するプログラムだけで（`ls build` や `npm ci` はチェックではありません）、チェックの終了コードがコマンド全体の結果になる場合に限ります。チェックが最後にあるか、後ろに `&&` だけが続く場合です（`npm test | tail` は数えません）。
- 同じ Bash コマンドが同じエラーで 2 回失敗すると、再試行をやめて根本原因を調べるよう Claude に伝えます（間で成功した後は、また伝えます）。
- `--no-verify`（`--no-ver` 以上の省略形を含む）を付けた git コマンドと、`git commit -n` / `-nm` を拒否します。サブシェル、`$(…)`、バッククォート、`bash -c "…"`、`eval`、`sudo` や `timeout` などのラッパーの中でも拒否します。オプションの値（`-m "…"`）、コメント、ヒアドキュメントの中の文字列では反応しません。その実行だけフックの場所を変える git コマンド（`-c core.hooksPath=…`、`--config-env core.hooksPath=…`）と、フック管理ツールを止める環境変数（`HUSKY=0`、`LEFTHOOK=0`、pre-commit の `SKIP=…`）を付けた git コマンドも拒否します。環境変数で設定を渡してフックの場所を変える形（`GIT_CONFIG_KEY_n=core.hooksPath`、`GIT_CONFIG_PARAMETERS`）も拒否します。ANSI-C クォート（`$'--no-\x76erify'`）、`env -S "…"`、`bash -c -- '…'`、標準入力からスクリプトを読むシェル（`bash <<< '…'`、ヒアドキュメント、`echo '…' | sh`）の中も読みます。完全には防げない補助的なガードで、git の alias（`git ci -n`）、事前に設定へ書き込んだフックの場所、前のコマンドで export した環境変数は検出しません。

### sandbox-lens

- `/sandbox-report` で、Bash の出力に現れた sandbox の拒否を、このセッション分と全期間分の両方について一覧表示します。拒否されたホストやパス、回数、最終発生時刻、コマンド例、許可する場合の設定を出します。
- `/sandbox-report reset` で記録を消去します。
- ヒントを出すだけで、sandbox の設定は変更しません。loopback やプライベートアドレスはポート付きでヒントに出します（例: `127.0.0.1:3000`）。ポートなしで登録すると全ポートが開くためです。
- 読むのは、出力の末尾にある `<sandbox_violations>` ブロックと、プログラム自身が出した `Operation not permitted` の行だけです。表示したファイルやページの中にあるブロックは無視します。コマンド例に含まれる認証情報（トークン、パスワード、`Authorization`/`Cookie` や `X-API-Key` などの認証ヘッダ、URL のユーザー情報、`PGPASSWORD` のような区切りのない名前も含む環境変数の代入の鍵、既知のキー形式）は伏せ字にします。各セクションは上位 10 件を表示し、記録が上限（200 件）に達すると、最後に見てから最も時間が経ったものが入れ替わります。

### skill-hint

プロンプトを送ると、それに合いそうな skill を最大 3 件、入力欄の上に出します（`💡 skill候補: /coding-debug …`）。出すのはセッションに実在する skill だけです。自動で起動はしません。「閉じる」か次のプロンプト（slash コマンドを含む）で消えます。すでに skill 名を含むプロンプト（どこかに `/name`、または `coding-debug` のようなハイフン付きの skill 名）には出しません。`/clear` のような組み込みコマンドや、`src/review/` のようなパスの一部は skill 名として数えません。plugin の skill（`plugin:name`）は完全な名前で提案します。

### todo-agent

- Claude のメインの返答で、行頭（引用記号やリスト記号の後でも可）に `#TODO(agent): <action>` がある行を、プロジェクト（リポジトリのルートか cwd）ごとに集めます。文中・表の中・インラインコードでの言及は TODO として扱いません。サブエージェントの返答は対象外です。
- `/todos` で、このプロジェクトの未完了項目をペインに出します。各項目に「完了」ボタンがあります。
- `/todos all` で、全プロジェクトの未完了項目を、保存済みのデータであることを明記してテキストで一覧表示します。
- 未完了の項目がある間は、ステータス行に `TODO(agent): N` と出ます。

### context-meter

ターンごとのコンテキスト使用率のスパークラインと、`ctx 63% ▲4 · 126k · turn in 120k / out 8k · $1.23` を帯に出します。最後のリクエストのコンテキストサイズに続けて、ターン全体の入出力（ターンが使用量を報告した場合のみ）を出します。使用率は 50% から黄色、80% から赤になります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `band` | `true` | 帯を描く（オフでも記録は続ける） |

### tool-row

完了したツール呼び出しを、Nerd Font のアイコン付きの 1 行に描き直します。Edit/Write は ` path +A −D`、Read は行数付き、Bash はエラーなら赤で、Agent、Web、MCP の呼び出しにも対応します。1 行にした呼び出しは下の結果ブロックを隠すので、1 呼び出しが 1 行になります（エラーの結果は残します）。他の mod が手を加えた行（image-preview のサムネイル付きの行）は結果も含めてそのまま残します。Claude Code が 1 行にまとめる連続呼び出し（`Read 3 files, ran 2 shell commands`）はまとめたままです。ターミナルのみです。

| 設定 | 既定値 | |
| --- | --- | --- |
| `compact` | `true` | オフにすると、すべての行と結果を Claude Code の元の表示のままにする |

### image-preview

- セッションが書き出した画像、読み込んだ画像、Bash コマンドが生成した画像（png、jpg、jpeg、webp、gif）について、ターミナルではそのツール行の下にサムネイルを出します（kitty graphics 対応の Ghostty、kitty）。
- `/images` でペインを開きます。新しい順に並び、`h`/`l` で切り替えます。
- PNG 以外は macOS の `sips` で変換します。変換はツールの結果を返した後に行うので、ツール呼び出しを待たせません。変換したファイルは専用のキャッシュ（`$TMPDIR` か `~/.cache`）に、新しい 50 件まで残します。

| 設定 | 既定値 | |
| --- | --- | --- |
| `inline` | `true` | ツール行の下にサムネイルを出す |
| `maxRows` | `12` | サムネイルが使える行数（1〜60） |

### self-audit

`minChars` 文字以上の返答ごとに、会話の fork（道具なし、ほぼプロンプトキャッシュから読まれる）に返答本文を引用データとして渡し、CLAUDE.md のルールに照らしてチェックします。対象は、根拠なしの完了宣言、1 行目が結果になっていない、未検証の断定、チェックの回避、範囲の膨張です。5 つのルールの違反で、引用が返答の中に実際にあるものだけを残します（作られた引用や定義外のルールは捨てます）。引用は Markdown の記号、箇条書き、引用符の種類、大文字小文字、空白、末尾の句点を無視して照合し、… で省略された引用は断片ごとに順に探します。違反は入力欄の上に赤字で出ます。「詳細」か `/self-audit` で、引用と fork の消費トークンを含むペインを開きます。結果は直前の返答のものだけで、監査されなかった場合はペインにその理由が出ます。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `true` | |
| `minChars` | `200` | これより短い返答はチェックしない |

コスト: ターンごとに、セッションのモデルで追加リクエストが 1 回走り、返答本文（最大 12,000 文字）がキャッシュされない入力として加わります。キャッシュが冷えていると（5 分以上空いた後やモデルの切り替え後）、会話全体を送り直します。

### context-diet

既定はオフです。オンにすると、skill 一覧をプロジェクトの種類に必要なものだけに絞ります。種類（Swift、Android、Rust、Web、Python、Go）は、リポジトリのルートとその 1 階層下から判定します。coding、quality、planning、research 系の skill は常に残し、red-team、`dynamic-*`、persona、operation 系は省きます。image、design 系と `ux-scan`、`brand-scan` は Rust、Python、Go のときに省きます。報告するのはメインの一覧だけです。省いた skill でも、プロンプトで名前を出せば、そのプロンプトには説明を添えます。

- `/context-diet` で、プロジェクトの種類、直近の一覧で残した skill と省いた skill、削減トークン数（推定）を表示します。確実に読み取れない形式の一覧は、そのまま送ります。
- `/context-diet on|off|reset` で、このセッションだけ設定を上書きします。切り替えると一覧を組み直すので、プロンプトキャッシュが 1 回効かなくなります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |
| `keep` | | 常に残す名前か `prefix*` のカンマ区切り。`drop` より優先 |
| `drop` | | 常に省く名前か `prefix*` のカンマ区切り |

### browser-cam

- Claude がブラウザを操作している間（Claude in Chrome、Claude Browser、リモートデバイスのブラウザ）、ペインに最新のスクリーンショット、ページのタイトルと URL、直近 8 件の操作（✓/✗）を出します。URL は navigate の呼び出しかタブ系ツール自身のヘッダからだけ取り、ページ本文からは取りません。
- `/cam` でペインを開閉します。フルスクリーンのターミナルでは、セッションで最初のブラウザ操作のときに 1 回だけ自動で開きます。スクリーンショットはペインを開いている間だけデコードし、セッション専用の非公開フォルダに書き出して、セッション終了時に削除します。
- デスクトップアプリでは、画像なしでタイトルと URL、キャプション、操作一覧を出します。

| 設定 | 既定値 | |
| --- | --- | --- |
| `autoOpen` | `true` | 最初のブラウザ操作で開く（フルスクリーンのターミナル） |

### prompt-coach

既定はオンです（`enabled: false` でオフ）。曖昧に見えるプロンプトの送信を止めます。曖昧とは、完了条件がなく対象も不明確な場合や、「いい感じ」のような評価語しかない場合です。帯には足りない点と、意図の推定候補が最大 3 つ出ます。候補は `clarify` skill の考え方で作ります（ありそうな解釈から順に、それぞれ別の成果物で、第三者が確かめられる完了条件付き）。

- `a` / `b` / `d` で、その候補を入力欄に入れます。編集して送れます（再び止めることはありません）
- `s: このまま送る` で、そのまま送ります
- `e: 補足して送る` で、`完了条件: ` を付けて入力欄に戻します（再び止めることはありません）
- `q: 閉じる` で、元の文を入力欄に戻します

代わりに別のプロンプトを打つと、そちらを送り、止めていた文を入力欄に戻します。止めた文は失われません。送信の失敗や下位での破棄、入力欄への書き戻しの失敗では、帯ごと保留したままにし（その間に別の文が保留されていればそちらを残す）、文をトーストで示します。保留中に `/clear` したときはすぐ入力欄に戻し、終了したときは同じプロジェクトの次の対話セッション開始時に戻します。入力欄が空ならそのまま入れ、その間に打った下書きがあればその後ろの行に追記し、上書きはしません。

slash コマンド、12 文字未満または 1500 文字を超えるプロンプト、添付や `@` 参照を含むもの、plugin が送ったもの、ターンの実行中に打ったプロンプトは判定しません。タイムアウトやエラーのときはそのまま送ります。同じ文を 2 回止めることはありません（直近 50 件の判定まで）。送信は最大 `timeoutMs` 待つことがあります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `true` | |
| `model` | `claude-haiku-5-5` | 判定に使うモデル（別名か ID） |
| `timeoutMs` | `3000` | 500〜3000 |

### loopback

既定はオフです。オンにすると、検出系 mod の新しい発見を、待機中に打った次のプロンプトに添えます。添えた内容はモデルだけが読み、人が打ち直さなくても補正が届きます。

- `self-audit`: 最後に監査された返信の違反
- `done-gate`: 編集後に通ったチェックがないこと（チェックが通ったあと新たな未検証の編集が出れば再度。帯の 閉じる で旗を下ろした場合は返しません）
- `sandbox-lens`: このセッションで見た拒否（各 1 回）

各発見はセッション中に 1 回だけ返し、誤りうるデータなので行動前に確かめるよう添えます。何件をどこから返したかはトーストに出ます。slash コマンド、隠しプロンプト、plugin が送ったもの、ターン実行中に打ったプロンプトには何も添えません。入れていない検出 mod の分は空です。

hit-rate がオンなら、hit-rate が止めたルールは返しません（`sandbox-lens` の拒否は止めません）。

- `/loopback` で、最後に返した内容と self-audit 再発率（返した違反のうち、次に監査された返信で再び指摘された割合。全セッション累計）を表示します。この割合で設計の当否を判定します（`.genius/decisions/loopback.md`）。hit-rate が止めたルールも表示します。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |

コスト: 発見は添えたプロンプトの入力として送られます（引用は 300 文字まで、最大 12 件）。

### zukan

セッションやリポジトリをまたいで使うエラー図鑑です。Bash のコマンドが失敗すると、エラー行を捕まえて番号を付けます。

- `📕 新種のエラー発見！ No.042「…」`: 初めて見る種類
- `📙 No.017 再会（3回目・未解決）`: 前にも見たが、直し方が分かっていない
- `` 📗 既知 No.017（3回目）— 前回: sandbox 外で `git push origin main` ``: 直し方が分かっている。Claude にもツール結果の横で、どこで見たか・何で通ったかを伝えます（指示ではなく、確かめるべき過去の記録として）

同じプログラムとサブコマンド（`git push`、`pnpm install`。先頭の `cd`・`export`・`source` は飛ばして読むので、`cd app && npm install` は `npm install`）が同じセッションの続く 10 回の Bash 呼び出し以内に成功すると、それを直し方として覚えます。sandbox 外で実行したかどうかも一緒に記録します。パス・引用・数値・ハッシュを除いてエラー行が一致すれば同じ種類として数えます。

テスト・lint・型チェック・ビルドの失敗は捕まえません（直すのはコードで、コマンドではないため）。記録するコマンドとエラー行の認証情報は sandbox-lens と同じ方法で伏せます。

- `/zukan` で図鑑を開きます。最近見たものから順に、種類数・解決済み・出会った回数を表示します
- `/zukan note <番号> <メモ>` で直し方を書き込みます。覚えたコマンドの代わりに表示し、Claude にも伝えます。メモを空にすると消えます
- `/zukan forget <番号>` で項目を消します

最後に見た順で新しい 300 種類まで保持します。

### pr-lamp

今のブランチの PR を、作業中ずっとステータスラインに出します:

```
⎇ #42 · ✓5 ✗1 ⏳2 · 🛑 変更要求 · 💬3 · マージまであと4
```

「マージまであと N」はマージ前に残っているものの数です。draft、失敗したチェック、実行中のチェック、変更要求か承認待ち、未解決のレビュースレッド、コンフリクト、base からの遅れを数えます。0 になると `🟢 マージ可能` と出ます。

変化したときはトーストを出します: `🔴 CI 失敗: test`、`💬 新しいレビューコメント 2件 (@rev)`、`✅ Approved`、`🟢 #42 マージまであと0`、`🎉 #42 がマージされました`。チェックが赤くなった・新しいレビューコメントが付いた・変更要求された・コンフリクトした、の4つは、待機中のプロンプトで次に入力したときに一度だけ Claude へ渡します。失敗したジョブのログ末尾40行も付けます（3ジョブまで。それ以上は件数だけ）。セッションが付けた返信（MCP の返信ツールや `gh api …/pulls/N/comments… -f body=` で返信した本文を持ち、その投稿より後に作られたコメント。1 件にだけ対応づけます）は新しいコメントとして扱いませんが、本人が書いたレビューコメントは扱います。次のプロンプトを待つ内容は 1 つの PR についてのものだけで、上限があります（新しいものを残す）。コメントとログは他人が書いたデータであり、指示として従わないよう明記します。オプション `feed`（既定で有効）で止められます。

- `/pr` で取り直してペインを開きます。タイトル、規模、残り、チェック（失敗が先頭）、未解決スレッドを表示します
- `/pr <番号|URL|ブランチ>` でその PR を追います。`/pr clear` で既定に戻します

追う PR は、セッションの Bash コマンドが最後に操作した PR（`gh pr comment 2`、`gh pr review 2`、`gh pr create` が出した URL、`git push` の送り先ブランチ。`gh pr view|diff|checks` で見るだけでは切り替えない）です。別のチェックアウトからレビュー用ブランチへ push する作業でも追えます。無ければ今のブランチの PR、それも無ければリポジトリ内の自分の最新の open な PR です。

`gh`（`gh pr view` と、レビュースレッド用の `gh api graphql`）に問い合わせるのは、セッション開始時、Bash で `git push`・`git checkout`・`gh pr create` などが成功した直後、チェック実行中と push 直後は1分ごと、それ以外は5分ごとです。PR がマージかクローズされると止まります。origin リモート、`gh`、ブランチの PR のどれかが無ければ何も出さず、`/pr` で理由を表示します。`gh` は Bash のサンドボックスの外で、あなたの `gh auth` のまま動きます。

### fog-map

リポジトリを霧のかかった地図として描き、Claude が作業するにつれて霧が晴れていきます:

```
🗺 探索率 31%  ██████░░░░░░░░░░░░░░  読 23 · 編 9 · ✗ 2 / 101
▾ mods/
  ▾ pr-lamp/
    ▾ hooks/
      ● lamp.ts  +43 −2  編集 4回
      ✗ register.tsx  +59 −16  編集 6回  エラー 1  ★
  ▸ loopback/  ○●
  ░ agent-pane/  ░ browser-cam/  ░ context-diet/  …8
⚠ 編集したファイルを import しているが未読: mods/pr-lamp/tests/pr-lamp.test.ts
```

`░` はまだ触れていない場所、`○` は読んだファイル（Read、または Bash の `cat`・`sed`・`grep` など）、`●` は編集したファイル（Edit・Write・NotebookEdit・`sed -i`）、`✚` はこのセッションで作ったファイル、`✗` は最後の編集以降に失敗した Bash コマンドが行番号付きで名指ししたファイル、`★` は直前に触ったファイルです。編集・新規・エラーを含むディレクトリは開き、読んだだけのディレクトリは閉じて中の印を横に並べます。同じ階層の触れていないディレクトリとファイルは、霧の 1 行にまとめます。

見落としの可能性が高いものを 2 種類警告します。読まずに編集したファイルと、編集したファイルを import しているのに一度も開いていないファイル（JS/TS と Python、`git grep` で検索）です。

- `/map` でペインを開きます
- ステータスラインに `🗺 31% · ●9 · ✗2 · ⚠1` を出し続けます
- 探索率が 25・50・75・100% を超えたとき、編集が初めて新しい区域に届いたときにトーストを出します（`🗺 新しい区域を開拓: mods/zukan/`）

地図はセッション単位で、サブエージェントの操作も含みます。リポジトリの外のファイルは描きません。探索率は触れたファイル数を `git ls-files` の数で割ったもので、checkout・pull・`mv`・`rm` の後に一覧を読み直します。非常に大きなリポジトリでは、一覧を 1 つの状態値に収まる分（パスで 300 万字）までにするので、一部ですが地図は描けます。git リポジトリの外では編集数だけを表示します。

### assertion-guard

Edit・Write・MultiEdit のたびに、呼び出し前後のファイル全体の差分を見ます（ファイル内で移動しただけの assertion は削除扱いせず、整形だけの変更（記号まわりの空白、末尾の `;` や `,`、両者を同じに読む言語での `'…'` と `"…"`）は書き換え扱いしません。文字列の中身が変われば書き換えです）。テストファイル（名前で判定、Rust はファイル内のどこかにテストモジュールがあるもの）では、assertion の削除やコメントアウト、厳しい matcher から緩い matcher への変更（`toEqual` → `toBeDefined`、`assertEqual` → `assertTrue`、`toThrow(X)` → `toThrow()`）、リテラルについての assertion への置き換え（`expect(true).toBe(true)`）、同じ assertion の期待値の書き換えや反転（`toBe` → `not.toBe`）、スキップや限定（`it.skip`、`@pytest.mark.skip`、`#[ignore]`、`t.Skip`）を拾います。どのファイルでも、新しく増えた例外の握りつぶし（`catch {}`、`.catch(() => undefined)`、`except: pass`、`|| true`）を拾います。

見つけた内容はデータとして引用して編集結果に添え、Claude に変更ごとの理由を明示するか戻すよう求めます。入力欄の上の帯は **確認済み** を押すまで残り、**理由を尋ねる** で質問をプロンプトに入れます。`/assertion-guard` でセッション中の一覧。正当なテスト更新も候補として出ます。変わった行を読むので、行に触れずに無効化した assertion（ブロックコメントで囲む、手前で `return` する）は見えません。

### negative-space

ソースへの編集で追加された認可（`isAdmin`、`permission`、`403` など）、入力検証（`validate`、`z.string().max(40)`、`if (x > 100)` など）、エラー処理（`catch`、`raise`、`Err(` など）を契機にします。ターン終了後、このセッションで触れたテスト（編集または Read したもの。ファイル名の語幹で対応付け。各テストは試しているケース・名前・数値だけを保持し（Read の行番号は除く）、合計 1.5 MB まで。契機のあるファイルのテストを最後まで残します）がまだ試していないもの — 拒否・不正入力・失敗時、境界値 N の N-1/N/N+1 — を帯に出します。試したとみなすのは、そのテストがケースを試し（`403`、`invalid`、`toThrow` など）、かつ変更したもの（契機の行がある関数名か、その行の名前）に触れている場合だけです。**Claude に頼む** で一覧をプロンプトへ、**不要** で閉じます。`/negative-space` で全候補。

### mutation-tap

`/mutate [テストコマンド]` は HEAD からの変更行（`git diff -U0`。まだ add していない新しいファイルは全行。対象は 20 ファイル・各 200 KB まで）に小さな改変（比較の反転、`&&`↔`||`、真偽値、`!` の除去、`+`↔`-`、定数 +1。文字列・コメント・import は対象外）を作り、ベースラインが通ることを確かめてから改変ごとにテストを実行します。実行はすべて `$TMPDIR/claude-mutation-tap/`（`TMPDIR` がなければ `~/.cache/claude-mutation-tap/`）に作るリポジトリの複製で行います（APFS では `cp -c`、対応するファイルシステムでは `cp --reflink` のコピーオンライト複製、それ以外は通常のコピー。依存やビルド成果物も含む）。作業ツリーには一切書き込まないので、実行中の編集・コミット・開発サーバに影響しません。複製は終了時に削除します。再読み込みや異常終了で残った複製は、その実行が 30 分止まっていれば後から始まったセッションが削除します（別のセッションが実行中の複製は消しません。以前のバージョンが残した複製は作成時刻しか分からないので 3 時間後）。実行中に複製が（一部でも）消えた場合は、改変を検出済みと数えずに失敗として終えます。複製からは Python のコンパイル済みファイルを除き、テスト中も書かせないので、直前の行のバイトコードで改変が実行されることはありません。すべての改変が生存したときは、テストが複製ではなく元のツリー（editable install・絶対パス・ビルド済みの dist）を読んでいる可能性をペインに示します。ペインには検出されなかった改変を表示します。`/mutate show`、`/mutate stop`。

| オプション | 既定値 | |
| --- | --- | --- |
| `maxMutants` | `20` | 変更行に散らして選ぶ |
| `timeoutSec` | `300` | 超えた実行は検出扱い |
| `testCommand` | `""` | Makefile・package.json・Cargo.toml・go.mod・pyproject.toml・Package.swift から推定 |

複製できないファイルシステム（APFS 以外のディスク上の大きな `node_modules` など）では、コピーに時間と容量がかかります。テストは Bash の sandbox の外（ホスト）で実行されます。

### perf-delta

- `/perf <コマンド>`: ウォームアップ 1 回と計測 N 回。初回は基準として保存し、以降は基準と比較（基準はコマンドと実行したフォルダごと）
- `/perf base <コマンド>`: 計測して基準として保存
- `/perf ref <git-ref> <コマンド>`: ref を一時的な `git worktree`（`mktemp` で作るフォルダ。セッションと同じ、最上位からのフォルダで実行）で計測してから作業ツリーを計測（`node_modules` など git にない依存はそこにありません）。実行中の worktree はロックします。git が消せなかった worktree はフォルダとその登録だけを削除し（自分の worktree を巻き込む `git worktree prune` は使いません）、中断で残ったものは 48 時間後に後のセッション開始時に削除します
- `/perf show`、`/perf clear [コマンド]`

時間とピークメモリは `/usr/bin/time`（macOS は `-l`、GNU は `-v`）から取ります。各側の中央値・±標準偏差・CV・範囲を出し、差は大きい方の標準偏差の 2 倍と 1% を超え、かつ各側 3 回以上計測したときだけ有意とし（それ未満は「回数が少なく判定できません」）、CV が 10% を超える側は不安定と警告します。ref の時点にないフォルダや、起動できないコマンドはそのように伝えます。

| オプション | 既定値 | |
| --- | --- | --- |
| `runs` | `5` | 3 以上 |
| `timeoutSec` | `300` | |

### handoff-capsule

セッション中の依頼、Claude の返答にある決定と未完了（`#TODO(agent)`、「まだ」、TODO リスト）、再実行する価値のある Bash コマンドと最後の結果、編集したファイルを追います（依頼・返答の行・TODO・コマンド中の認証情報は zukan と同じく伏せます）。カプセルは圧縮の前、セッション終了時、`/handoff save` で保存します（リポジトリごとに 5 件）。人の気配がないセッション（画面がつながらず入力もない `-p` 実行や SDK。現状の Claude Code for VS Code のように画面をつながないホストもこれに数えます）はリポジトリごとに 1 件だけ残すので、自動実行が人のカプセルを押し出すことはなく、人のカプセルを先に出します。再開したセッションは自分のカプセルに書き足し、ほかのカプセルは出しません。`/clear` 後の会話は新しいカプセルとして始まり、直前に残したものを出します。マスク導入前に残したカプセルも、読むときに伏せます。同じリポジトリの次のセッション、または圧縮直後の会話で帯が出るので、目的・決定・未完了・コマンド・ファイルを切り替えて **取り込む** を押すと、選んだ部分が次のプロンプトと一緒に「現状と照合すべき記録」として Claude に渡ります。`/handoff` で表示、`/handoff load` で最新を再提示。

### port-lantern

バックグラウンド実行の Bash コマンドやサーバ起動コマンド（`pnpm dev`、`vite`、`uvicorn`、`rails s` など）を追い、出力ファイルを 5 秒ごとに読んでローカル URL とポートを拾い（コマンドの `--port`・`PORT=` も）、`lsof` で待ち受けているかを確かめます。ステータスラインに `🏮 :5173● :8000○`、起動・停止はトーストで。`/ports` のペインに URL（押すとコピー）、コマンド、pid、直近のログ（エラーは赤）を出します。

### artifact-shelf

呼び出しが作ったデータ・文書・画像・動画・音声・パッチ・アーカイブ: Write のファイル、Bash の `-o`/`--output`/`>`/`tee` の行き先や変換コマンドの出力、ツールの応答に出てくるパス。呼び出し中に更新されたことを確かめてから、サイズ・時刻・呼び出し・依頼と一緒にリポジトリごとに保存します（セッションをまたいで 300 件。依頼とコマンド中の認証情報は zukan と同じく伏せ、以前に保存した分も次のセッション開始時に伏せて書き戻します。保存するのは最近追加のあった 16 リポジトリ分までで、古いものから消えます）。`/shelf [語…]` で種類（`動画`、`video`）、拡張子（`csv`）、時刻（`今日`、`昨日`、`7d`）、文字列で絞り込み。ペインでは種類で絞り、名前を押すとパスをコピー。削除されたファイルは消さずに印を付けます。

### focus-hud

```
🎯 ログインのバグを直して › Writing tests · 📄 auth.ts · ⚙ Bash pnpm test · ⏳ Bash の終了待ち (12s)
```

目的は最新の依頼の 1 行目と進行中の TODO、対象は最後に触れたファイル・ページのホスト・プログラム、実行中は進行中の呼び出し、待ちは許可・あなたへの質問・ツール・サブエージェント・モデル・あなたの入力。`/focus` で同じ内容を複数行で。

### side-effect-ledger

作業ツリーの外を変える Bash コマンドとツール呼び出しを記録します: `git push`（取り消し方を push の出力から作る: `git push --force-with-lease=main:<new> origin <old>:main`、新規ブランチは `--delete`。1 行で複数回 push した場合はそれぞれのリモートの ref だけを使い、`git -C dir push` も対象）、`gh pr|issue|release|repo …`、`gh api -X POST…`、npm/cargo/PyPI/gem の公開、docker push、kubectl、helm、terraform、pulumi、cdk、vercel、netlify、fly、wrangler、firebase、gcloud、aws、ローカル以外への `curl -X POST|PUT|PATCH|DELETE`、リモートへの scp/rsync、作成・更新・送信する MCP ツール、Artifact の公開・削除。失敗した呼び出しには取り消し方を付けません（ただし途中まで反映され得るもの、つまり push で動いた ref は残し、失敗したインフラ操作は「途中まで反映された可能性あり、まず状態を確認」とだけ示す）。取り消し方には、対象を指していたもの（`KUBECONFIG`、`HELM_NAMESPACE`、`GH_REPO`、`kubectl --context/-n`）も付けます。トークンは付けません。dry-run（`--dry-run`、`git push -n`）と読み取り（`kubectl rollout status`、`terraform state list`、`wrangler pages dev`）は記録しません。各項目に結果（失敗も）、取り消し方と難しさを残し（取り消し方は以前からあったかもしれないものを消さない: クローズや削除（`gh pr close <url>`、`gh release delete`、`gh repo delete`、`helm uninstall`）は、この呼び出しで作ったと出力が示すときだけ出す（最後の URL、その release 自身のタグ、"already exists" がないこと。同じ行に別の gh・helm コマンドがあれば出力がどちらのものか分からないので出さない。`| tail` や `|| true` の陰の失敗は終了コード 0 になるため）。`gh pr close` は head ブランチを、`gh release delete` はタグを残す。別のディレクトリ（`cd`、`git -C`、サブシェル）での push はリモートを git が出力した URL で名指しし、戻す sha は出力がその 1 回の push のものと確実な場合だけ示す）、`/ledger` で取り消し方を確かめたら **確認済みにする** か **不要** にします。ステータスラインにセッションの件数と未確認数。コマンド中の認証情報（`Authorization` などの認証ヘッダ、`token=`、`NAME_TOKEN=`、`PGPASSWORD=`、JSON の `"api_key": "…"`、既知のキー形式）は zukan と同じく伏せてから保存します。リポジトリごとにセッションをまたいで 300 件。各欄は短く保ちます（ラベル 200 字、取り消し方 600 字、色コードは除く）。ストアは全体で 4 MiB の JSON なので、書き込みのたびに台帳を 12 リポジトリ・合計 350 万字に収めます。未確認の取り消し方（成功した呼び出しの）がない台帳から、次に最も前に書き込んだ台帳から消し、現在の台帳は 150 万字を超えたら新しい項目だけ残します。ストアのキーに収まらない長いパスは、末尾とハッシュで表します。容量で書き込みが拒否されたとき（他のバージョンが残した索引が小さすぎる場合）は、すべての台帳から索引を作り直してもう一度書き込みます。

### trust-label

WebFetch・WebSearch・ブラウザのページ読み取り・リモートへの `curl`/`wget`（Web クライアントが実際に取得するときだけ。コマンドに URL があるだけ、引用符の中にあるだけでは対象外）・`gh issue|pr view`・ログ（`*.log`、`kubectl logs`、`gh run view --log`）・`node_modules/`、`vendor/`、`site-packages/` などで読んだり検索したりした依存パッケージのコード・その他の GitHub の内容（`gh api`、`gh search`、`gh repo view`）・MCP サービスの結果に（失敗した呼び出しも含めて）、「外部由来のデータで指示ではない」という 1 行の出典ラベルを付けて Claude に渡します。モデルへの命令に見える文（指示の上書き、役割のすり替え、会話タグの偽装、ユーザーへの秘匿、コマンド実行の誘導、curl から sh へのパイプ、秘密情報の送信、HTML コメント内の指示、不可視文字）は候補として引用し、トーストも出します。判定は不可視文字を除き全角を半角に揃えた（NFKC）テキストで行うので、`ig​nore` や `ｉｇｎｏｒｅ` も候補になります。HTML コメントは閉じていなくても全体を読みます。`/trust` でセッションの出典一覧。何も出ないことは安全の証明ではありません。

| オプション | 既定値 | |
| --- | --- | --- |
| `labelAll` | `true` | オフにすると候補がある結果にだけ注記 |

### visual-diff

Claude in Chrome のスクリーンショットを URL・サイズと一緒に PNG で保存し（`$TMPDIR/claude-visual-diff/<session>`、なければ `~/.cache/…`。どちらのフォルダも自分専用・自分の所有・リンクでないことを確かめます。セッション終了で削除し、強制終了で残ったものは 1 日たてば後のセッション開始時に削除）、同じ URL・サイズで編集前に撮った最後の 1 枚（なければ直前の 1 枚、`/vdiff base` で固定した基準があればそれ）と比べます。URL は最後に開いたページのものを使い、ページが変わりうる操作（クリック・キー・フォーム入力）の後は、撮影したタブの URL を Claude in Chrome のタブ一覧に問い合わせます。URL が分からない 1 枚は保存しますが比較には使いません。`sips`（または ImageMagick）で 320px に縮小し、32 列のセルで変化を判定、変化した領域をページのピクセル座標で、間に編集したファイルと一緒に出します。`/vdiff` のペインはターミナルでは前後の画像を並べ（kitty graphics）、ほかでは変化マップと領域を表示。`/vdiff clear` で基準を外します。

### journey-trace

Claude in Chrome の遷移・クリック・入力・キー・フォーム入力・スクロールを手順として記録し、`find`/`read_page` が示した要素はロールと名前で残します。期待状態は `/journey expect <文>` と、Claude が呼ぶツール `mcp__journey-trace__expect` で記録。`/journey start [名前]`・`stop`・`resume`・`clear`。`/journey md` でバグ報告（再現手順・期待結果・実際の結果の記入欄・環境）、`/journey e2e` で Playwright テストの下書き（座標だけのクリックは TODO）をコピーします。秘密の値は記録しません。秘密を示す名前の欄（パスワード・トークン・ワンタイムパスワード・PIN・セキュリティコードなど）への入力、その欄にフォーカスがある間の入力、既知のキー形式の文字列は `***` として残し、報告にはその旨を、テストでは `process.env.JOURNEY_SECRET_n` を使います。欄が分からないとき（Tab や Enter の後、座標でのクリック、新しいページ）は、パスワードやワンタイムコードらしい文字列も伏せます。URL はクエリとフラグメントの秘密のパラメータ（`token`・`signature`・`sessionId` など、コールバックのページの `code`）、パス中のキー形式の文字列、ユーザー部分を伏せます。選択欄やチェックボックスへの入力は `selectOption` や `check` で書き出します。

### token-lens

トークンはリポジトリのスタイルシート（`--name:` のカスタムプロパティ、SCSS の `$変数`）と tokens JSON（`$value`/`value`）から読み、参照を解決します。`/token-lens <セレクタ>`（引数なしならページで選択したテキスト）で、Claude が操作中のタブに Claude in Chrome の `javascript_tool` でスクリプトを流し、最大 5 要素の色・背景・枠線・margin・padding・gap・角丸・フォント・サイズ・太さ・行高・字間を照合します: トークンと一致、または独自値と最寄りのトークンとの差。`/token-lens tokens` で読み込んだ件数、`/token-lens reload` で読み直し。

### hit-rate

既定はオフです。オンにすると、各発見に後から判定を付けます。判定の材料はその後セッションで起きたことだけで、判定用のモデルは使いません。

| ルール | 当たり（tp） | 外れ（fp） |
| --- | --- | --- |
| `done-gate:unverified` | 旗の後で最初のテスト・lint・型チェック・ビルドが失敗 | 一発で成功 |
| `assertion-guard:<kind>` | 後の編集で弱めた変更が戻された（元の行が戻り、新しい行が消える。重複行は数で区別）。1 回の編集で複数の弱め方をした場合は種類ごとに判定 | 人が確認済みにした後、丸 1 ターン経ってもそのまま |
| `self-audit:R1`〜`R5` | 次に監査された返信でその違反が消えた | 同じ違反が再び出た |
| `zukan:recall` | 伝えた前回の直し方でエラーを抜けた | 別のコマンドで抜けた |

判定できないものは unknown として数えます（閉じる で下ろした done-gate の帯、zukan が待つのをやめたエラー、セッション終了時に未判定のもの）。同じエラーが別のコマンドで再び出ても、同じ recall として待ち続けます。件数はセッションをまたいで記録します。当たりと外れの合計が `minN` 以上で、的中率が `threshold` 未満のルールを `muted` に載せ、loopback はそのルールを返しません（検出 mod の帯は今まで通り出ます）。

- `/hit-rate` で、ルールごとの TP / FP / unknown・的中率・n、unknown の割合、このセッションの最近の判定を表示します。この数字で設計の当否を判定します（`.genius/decisions/hit-rate.md`）。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |
| `minN` | `20` | ルールを止める判断に必要な判定数 |
| `threshold` | `0.5` | これ未満の的中率でルールを止める（0〜1。`50` など範囲外の値は無視して既定値を使い、`/hit-rate` に表示） |

判定は代理指標です。チェックの失敗が編集と無関係なこともあり、違反が再び出ないのは単にその場面がなかっただけかもしれません。止めたルールも判定は続けるので、的中率が戻れば再び返します。

## 開発

```
claude plugin validate mods/<mod>
claude plugin test mods/<mod>
claude --plugin-dir mods/<mod>
scripts/check-copies.sh
```

mod 同士はコードを共有できないため、一部のファイルは別の mod の写しです（`mods/zukan/hooks/shell.ts` と `mods/hit-rate/hooks/shell.ts` は done-gate のもの、side-effect-ledger・handoff-capsule・artifact-shelf の `mask.ts` は zukan のもの）。写しがずれると `scripts/check-copies.sh` が失敗します。
