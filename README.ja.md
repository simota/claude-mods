# claude-mods

[English](README.md) | 日本語

個人用の Claude Code mod（function hook の plugin）集です。1 つの marketplace として公開しています。

| Mod | できること |
| --- | --- |
| `agent-pane` | セッションのサブエージェントをペインで表示。実行中は経過時間、完了したものは結果と所要時間 |
| `done-gate` | 未検証の変更を指摘し、同じ失敗の繰り返しを止め、`git --no-verify` を拒否 |
| `sandbox-lens` | Bash 出力に現れた sandbox の拒否を集計し、`/sandbox-report` で報告 |
| `battle-report` | ターンごとに RPG 風の戦果報告（トークン、編集数、増減行数、ツールエラー）をトースト・通知・効果音で |
| `skill-hint` | 入力したプロンプトに合う skill を最大 3 件、入力欄の上に提案（自動では起動しない） |
| `todo-agent` | Claude の返答にある `#TODO(agent)` をプロジェクトごとに集め、`/todos` ペインで管理 |
| `context-meter` | 入力欄の上に、ターンごとのコンテキスト使用率のスパークライン（Gruvbox 配色）とトークン数・コスト |
| `tool-row` | ターミナルで、完了したツール呼び出しの行を、Nerd Font のアイコンと Gruvbox 配色、短い統計付きの 1 行に描き直す |
| `image-preview` | セッションが書き出し・読み込み・生成した画像のサムネイルを、ツール行の下と `/images` ペインに表示 |
| `self-audit` | ターンごとに会話の fork（キャッシュ利用）で Claude 自身の返答を CLAUDE.md の報告ルールに照らし、違反を入力欄の上に表示 |
| `context-diet` | skill 一覧をプロジェクトの種類に必要なものだけに絞る（既定オフ）。`/context-diet` で省いた skill と削減トークン数を表示 |
| `browser-cam` | Claude が操作中のブラウザをペインで表示。Claude in Chrome の最新スクリーンショット、ページの URL、直近の操作 |
| `prompt-coach` | 曖昧に見えるプロンプト（完了条件がない、対象が不明確）の送信を止め、意図の推定候補・そのまま送る・補足するから選ばせる（既定オフ） |
| `loopback` | self-audit・done-gate・sandbox-lens の発見を、人に見せるだけでなく次のプロンプトに添えて Claude へ返す（既定オフ） |
| `zukan` | エラー図鑑: セッションやリポジトリをまたいで Bash のエラーを集め、通った直し方を記録し、同じエラーが再び出たら前回の直し方を Claude と人に伝える |
| `pr-lamp` | 今のブランチの PR を信号灯に: CI・レビュー・未解決スレッド・マージまでの残りをステータスラインと `/pr` ペインに出し、赤くなったチェックと新しいレビューコメントを次のプロンプトと一緒に Claude へ渡す |

## インストール

ターミナルのセッションのプロンプトで:

```
/plugin install <mod> --marketplace simota/claude-mods
```

シェルから:

```
claude plugin install <mod> --marketplace simota/claude-mods
```

このリポジトリは private です。インストールには、GitHub での読み取り権限と、そのマシンにある github.com 用の git 認証情報（SSH 鍵、または `gh auth login` のあと `gh auth setup-git`）が必要です。

## 使い方

設定は、セッション内では `/plugin configure <mod>@simota-mods`、シェルからは次のコマンドで変えられます。

```
echo '{"enabled":"true"}' | claude plugin configure <mod>@simota-mods --values-stdin
```

`/plugin configure` で変えた設定はその場で mod を読み込み直して反映され、シェルから変えた設定は再起動後に反映されます。入力欄の上の帯は積み重なります。各 mod は、他の mod が描いた内容の上に自分の行を描きます。

### agent-pane

- `/agent-pane` でペインを開きます。実行中のサブエージェントが経過時間付きで先に並び、その後に完了したものが ✓/✗ と所要時間付きで並びます。結果が分からないまま一覧から消えたバックグラウンド実行は `? 結果不明`、teammate やリモートでの起動は `↗ 起動済み（追跡外）` と出ます。
- フルスクリーンのターミナルでは、セッションで最初に Agent を呼んだときに 1 回だけ自動で開きます（リロードしても再び開きません）。
- 実行中のものがある間は、ステータス行に `agents: N running` と出ます。

### done-gate

コマンドはなく、自動で働きます。

- ファイルを編集したあとにテスト・lint・型チェック・ビルドが成功しないままターンが終わると、「未検証の変更があります」の帯が出ます。チェックが成功するか「閉じる」を押すまで残ります。判定するのはコマンドが実行するプログラムだけで（`ls build` や `npm ci` はチェックではありません）、チェックの終了コードがコマンド全体の結果になる場合に限ります。チェックが最後にあるか、後ろに `&&` だけが続く場合です（`npm test | tail` は数えません）。
- 同じ Bash コマンドが同じエラーで 2 回失敗すると、再試行をやめて根本原因を調べるよう Claude に伝えます（間で成功した後は、また伝えます）。
- `--no-verify`（`--no-ver` 以上の省略形を含む）を付けた git コマンドと、`git commit -n` / `-nm` を拒否します。サブシェル、`$(…)`、バッククォート、`bash -c "…"`、`eval`、`sudo` や `timeout` などのラッパーの中でも拒否します。オプションの値（`-m "…"`）、コメント、ヒアドキュメントの中の文字列では反応しません。その実行だけフックの場所を変える git コマンド（`-c core.hooksPath=…`、`--config-env core.hooksPath=…`）と、フック管理ツールを止める環境変数（`HUSKY=0`、`LEFTHOOK=0`、pre-commit の `SKIP=…`）を付けた git コマンドも拒否します。完全には防げない補助的なガードで、git の alias（`git ci -n`）、事前に設定へ書き込んだフックの場所、前のコマンドで export した環境変数は検出しません。

### sandbox-lens

- `/sandbox-report` で、Bash の出力に現れた sandbox の拒否を、このセッション分と全期間分の両方について一覧表示します。拒否されたホストやパス、回数、最終発生時刻、コマンド例、許可する場合の設定を出します。
- `/sandbox-report reset` で記録を消去します。
- ヒントを出すだけで、sandbox の設定は変更しません。loopback やプライベートアドレスはポート付きでヒントに出します（例: `127.0.0.1:3000`）。ポートなしで登録すると全ポートが開くためです。
- 読むのは、出力の末尾にある `<sandbox_violations>` ブロックと、プログラム自身が出した `Operation not permitted` の行だけです。表示したファイルやページの中にあるブロックは無視します。コマンド例に含まれる認証情報（トークン、パスワード、`Authorization`/`Cookie` ヘッダ、URL のユーザー情報、環境変数の代入に含まれる鍵）は伏せ字にします。各セクションは上位 10 件を表示し、記録が上限（200 件）に達すると、最後に見てから最も時間が経ったものが入れ替わります。

### battle-report

ターンが終わるたびに、そのターンのトークン数（キャッシュの読み書きを含む）、編集数、Edit/Write による増減行数（Bash での変更は数えず、git コマンドも実行しません）、ツールエラー数を、トースト・OS 通知・効果音で知らせます。API エラーや拒否で終わったターンは Basso で失敗として報告し、中断したターンは報告しません。hook、権限ルール、本人が拒否した呼び出しはエラーに数えません。

| 設定 | 既定値 | |
| --- | --- | --- |
| `sound` | `true` | エラーなしなら Glass、ツールエラーがあれば Basso（afplay、macOS） |
| `notify` | `true` | トーストに加えて OS 通知も出す |
| `quietTurns` | `true` | ツールを呼ばなかったターンは報告しない |

### skill-hint

プロンプトを送ると、それに合いそうな skill を最大 3 件、入力欄の上に出します（`💡 skill候補: /coding-debug …`）。出すのはセッションに実在する skill だけです。自動で起動はしません。「閉じる」か次のプロンプト（slash コマンドを含む）で消えます。すでに skill 名を含むプロンプト（どこかに `/name`、または `coding-debug` のようなハイフン付きの skill 名）には出しません。`/clear` のような組み込みコマンドや、`src/review/` のようなパスの一部は skill 名として数えません。plugin の skill（`plugin:name`）は完全な名前で提案します。

### todo-agent

- Claude のメインの返答で、行頭（引用記号やリスト記号の後でも可）に `#TODO(agent): <action>` がある行を、プロジェクト（リポジトリのルートか cwd）ごとに集めます。文中・表の中・インラインコードでの言及は TODO として扱いません。サブエージェントの返答は対象外です。
- `/todos` で、このプロジェクトの未完了項目をペインに出します。各項目に「完了」ボタンがあります。
- `/todos all` で、全プロジェクトの未完了項目を、保存済みのデータであることを明記してテキストで一覧表示します。
- 未完了の項目がある間は、ステータス行に `TODO(agent): N` と出ます。

### context-meter

ターンごとのコンテキスト使用率のスパークラインと、`ctx 63% ▲4 · 126k · turn in 120k / out 8k · $1.23` を帯に出します。最後のリクエストのコンテキストサイズに続けて、ターン全体の入出力（ターンが使用量を報告した場合のみ）を出します。使用率は 50% から黄色、80% から赤になります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `band` | `true` | 帯を描く（オフでも記録は続ける） |

### tool-row

完了したツール呼び出しを、Nerd Font のアイコン付きの 1 行に描き直します。Edit/Write は ` path +A −D`、Read は行数付き、Bash はエラーなら赤で、Agent、Web、MCP の呼び出しにも対応します。1 行にした呼び出しは下の結果ブロックを隠すので、1 呼び出しが 1 行になります（エラーの結果は残します）。他の mod が手を加えた行（image-preview のサムネイル付きの行）は結果も含めてそのまま残します。Claude Code が 1 行にまとめる連続呼び出し（`Read 3 files, ran 2 shell commands`）はまとめたままです。ターミナルのみです。

| 設定 | 既定値 | |
| --- | --- | --- |
| `compact` | `true` | オフにすると、すべての行と結果を Claude Code の元の表示のままにする |

### image-preview

- セッションが書き出した画像、読み込んだ画像、Bash コマンドが生成した画像（png、jpg、jpeg、webp、gif）について、ターミナルではそのツール行の下にサムネイルを出します（kitty graphics 対応の Ghostty、kitty）。
- `/images` でペインを開きます。新しい順に並び、`h`/`l` で切り替えます。
- PNG 以外は macOS の `sips` で変換します。変換はツールの結果を返した後に行うので、ツール呼び出しを待たせません。変換したファイルは専用のキャッシュ（`$TMPDIR` か `~/.cache`）に、新しい 50 件まで残します。

| 設定 | 既定値 | |
| --- | --- | --- |
| `inline` | `true` | ツール行の下にサムネイルを出す |
| `maxRows` | `12` | サムネイルが使える行数（1〜60） |

### self-audit

`minChars` 文字以上の返答ごとに、会話の fork（道具なし、ほぼプロンプトキャッシュから読まれる）に返答本文を引用データとして渡し、CLAUDE.md のルールに照らしてチェックします。対象は、根拠なしの完了宣言、1 行目が結果になっていない、未検証の断定、チェックの回避、範囲の膨張です。違反は入力欄の上に赤字で出ます。「詳細」か `/self-audit` で、引用と fork の消費トークンを含むペインを開きます。結果は直前の返答のものだけで、監査されなかった場合はペインにその理由が出ます。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `true` | |
| `minChars` | `200` | これより短い返答はチェックしない |

コスト: ターンごとに、セッションのモデルで追加リクエストが 1 回走り、返答本文（最大 12,000 文字）がキャッシュされない入力として加わります。キャッシュが冷えていると（5 分以上空いた後やモデルの切り替え後）、会話全体を送り直します。

### context-diet

既定はオフです。オンにすると、skill 一覧をプロジェクトの種類に必要なものだけに絞ります。種類（Swift、Android、Rust、Web、Python、Go）は、リポジトリのルートとその 1 階層下から判定します。coding、quality、planning、research 系の skill は常に残し、red-team、`dynamic-*`、persona、operation 系は省きます。image、design 系と `ux-scan`、`brand-scan` は Rust、Python、Go のときに省きます。報告するのはメインの一覧だけです。省いた skill でも、プロンプトで名前を出せば、そのプロンプトには説明を添えます。

- `/context-diet` で、プロジェクトの種類、直近の一覧で残した skill と省いた skill、削減トークン数（推定）を表示します。確実に読み取れない形式の一覧は、そのまま送ります。
- `/context-diet on|off|reset` で、このセッションだけ設定を上書きします。切り替えると一覧を組み直すので、プロンプトキャッシュが 1 回効かなくなります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |
| `keep` | | 常に残す名前か `prefix*` のカンマ区切り。`drop` より優先 |
| `drop` | | 常に省く名前か `prefix*` のカンマ区切り |

### browser-cam

- Claude がブラウザを操作している間（Claude in Chrome、Claude Browser、リモートデバイスのブラウザ）、ペインに最新のスクリーンショット、ページのタイトルと URL、直近 8 件の操作（✓/✗）を出します。URL は navigate の呼び出しかタブ系ツール自身のヘッダからだけ取り、ページ本文からは取りません。
- `/cam` でペインを開閉します。フルスクリーンのターミナルでは、セッションで最初のブラウザ操作のときに 1 回だけ自動で開きます。スクリーンショットはペインを開いている間だけデコードし、セッション専用の非公開フォルダに書き出して、セッション終了時に削除します。
- デスクトップアプリでは、画像なしでタイトルと URL、キャプション、操作一覧を出します。

| 設定 | 既定値 | |
| --- | --- | --- |
| `autoOpen` | `true` | 最初のブラウザ操作で開く（フルスクリーンのターミナル） |

### prompt-coach

既定はオフです。オンにすると、曖昧に見えるプロンプトの送信を止めます。曖昧とは、完了条件がなく対象も不明確な場合や、「いい感じ」のような評価語しかない場合です。帯には足りない点と、意図の推定候補が最大 3 つ出ます。候補は `clarify` skill の考え方で作ります（ありそうな解釈から順に、それぞれ別の成果物で、第三者が確かめられる完了条件付き）。

- `a` / `b` / `d` で、その候補を入力欄に入れます。編集して送れます（再び止めることはありません）
- `s: このまま送る` で、そのまま送ります
- `e: 補足して送る` で、`完了条件: ` を付けて入力欄に戻します（再び止めることはありません）
- `q: 閉じる` で、元の文を入力欄に戻します

代わりに別のプロンプトを打つと、そちらを送り、止めていた文を入力欄に戻します。

slash コマンド、12 文字未満または 1500 文字を超えるプロンプト、添付や `@` 参照を含むもの、plugin が送ったもの、ターンの実行中に打ったプロンプトは判定しません。タイムアウトやエラーのときはそのまま送ります。同じ文を 2 回止めることはありません（直近 50 件の判定まで）。送信は最大 `timeoutMs` 待つことがあります。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |
| `model` | `claude-haiku-5-5` | 判定に使うモデル（別名か ID） |
| `timeoutMs` | `3000` | 500〜3000 |

### loopback

既定はオフです。オンにすると、検出系 mod の新しい発見を、待機中に打った次のプロンプトに添えます。添えた内容はモデルだけが読み、人が打ち直さなくても補正が届きます。

- `self-audit`: 最後に監査された返信の違反
- `done-gate`: 編集後に通ったチェックがないこと（チェックが通ったあと新たな未検証の編集が出れば再度。帯の 閉じる で旗を下ろした場合は返しません）
- `sandbox-lens`: このセッションで見た拒否（各 1 回）

各発見はセッション中に 1 回だけ返し、誤りうるデータなので行動前に確かめるよう添えます。何件をどこから返したかはトーストに出ます。slash コマンド、隠しプロンプト、plugin が送ったもの、ターン実行中に打ったプロンプトには何も添えません。入れていない検出 mod の分は空です。

- `/loopback` で、最後に返した内容と self-audit 再発率（返した違反のうち、次に監査された返信で再び指摘された割合。全セッション累計）を表示します。この割合で設計の当否を判定します（`.genius/decisions/loopback.md`）。

| 設定 | 既定値 | |
| --- | --- | --- |
| `enabled` | `false` | |

コスト: 発見は添えたプロンプトの入力として送られます（引用は 300 文字まで、最大 12 件）。

### zukan

セッションやリポジトリをまたいで使うエラー図鑑です。Bash のコマンドが失敗すると、エラー行を捕まえて番号を付けます。

- `📕 新種のエラー発見！ No.042「…」`: 初めて見る種類
- `📙 No.017 再会（3回目・未解決）`: 前にも見たが、直し方が分かっていない
- `` 📗 既知 No.017（3回目）— 前回: sandbox 外で `git push origin main` ``: 直し方が分かっている。Claude にもツール結果の横で、どこで見たか・何で通ったかを伝えます（指示ではなく、確かめるべき過去の記録として）

同じプログラムとサブコマンド（`git push`、`pnpm install`）が同じセッションの続く 10 回の Bash 呼び出し以内に成功すると、それを直し方として覚えます。sandbox 外で実行したかどうかも一緒に記録します。パス・引用・数値・ハッシュを除いてエラー行が一致すれば同じ種類として数えます。

テスト・lint・型チェック・ビルドの失敗は捕まえません（直すのはコードで、コマンドではないため）。記録するコマンドとエラー行の認証情報は sandbox-lens と同じ方法で伏せます。

- `/zukan` で図鑑を開きます。最近見たものから順に、種類数・解決済み・出会った回数を表示します
- `/zukan note <番号> <メモ>` で直し方を書き込みます。覚えたコマンドの代わりに表示し、Claude にも伝えます。メモを空にすると消えます
- `/zukan forget <番号>` で項目を消します

最後に見た順で新しい 300 種類まで保持します。

### pr-lamp

今のブランチの PR を、作業中ずっとステータスラインに出します:

```
⎇ #42 · ✓5 ✗1 ⏳2 · 🛑 変更要求 · 💬3 · マージまであと4
```

「マージまであと N」はマージ前に残っているものの数です。draft、失敗したチェック、実行中のチェック、変更要求か承認待ち、未解決のレビュースレッド、コンフリクト、base からの遅れを数えます。0 になると `🟢 マージ可能` と出ます。

変化したときはトーストを出します: `🔴 CI 失敗: test`、`💬 新しいレビューコメント 2件 (@rev)`、`✅ Approved`、`🟢 #42 マージまであと0`、`🎉 #42 がマージされました`。チェックが赤くなった・新しいレビューコメントが付いた・変更要求された・コンフリクトした、の4つは、待機中のプロンプトで次に入力したときに一度だけ Claude へ渡します。失敗したジョブのログ末尾40行も付けます。コメントとログは他人が書いたデータであり、指示として従わないよう明記します。オプション `feed`（既定で有効）で止められます。

- `/pr` で取り直してペインを開きます。タイトル、規模、残り、チェック（失敗が先頭）、未解決スレッドを表示します
- `/pr <番号|URL|ブランチ>` でその PR を追います。`/pr clear` で既定に戻します

追う PR は、セッションの Bash コマンドが最後に指した PR（`gh pr diff 2`、`gh pr create` が出した URL、`git push` の送り先ブランチ）です。別のチェックアウトからレビュー用ブランチへ push する作業でも追えます。無ければ今のブランチの PR、それも無ければリポジトリ内の自分の最新の open な PR です。

`gh`（`gh pr view` と、レビュースレッド用の `gh api graphql`）に問い合わせるのは、セッション開始時、Bash で `git push`・`git checkout`・`gh pr create` などが成功した直後、チェック実行中と push 直後は1分ごと、それ以外は5分ごとです。PR がマージかクローズされると止まります。origin リモート、`gh`、ブランチの PR のどれかが無ければ何も出さず、`/pr` で理由を表示します。`gh` は Bash のサンドボックスの外で、あなたの `gh auth` のまま動きます。

## 開発

```
claude plugin validate mods/<mod>
claude plugin test mods/<mod>
claude --plugin-dir mods/<mod>
scripts/check-copies.sh
```

mod 同士はコードを共有できないため、一部のファイルは別の mod の写しです（`mods/zukan/hooks/shell.ts` は done-gate のもの）。写しがずれると `scripts/check-copies.sh` が失敗します。
